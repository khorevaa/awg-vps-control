# Модель локальных инструментов установки

Инструменты — отдельный CLI-режим бинарника Control, запускаемый root при установке, обслуживании и выдаче доступа. Они не являются API хостовой WARP-службы и не запускают VPN-команды.

| Модель | Поля и назначение |
| --- | --- |
| installDirectory | `path: string`, `uid: int`, `gid: int`, `mode: os.FileMode`: фиксированные каталоги с владельцами и правами |
| manualPolicy | `configured`, `warp_enabled`, `allow_direct_without_warp`: bool; `revision`: string. Снимок перед явным ручным выбором режима, ревизия защищает от перезаписи параллельного изменения. |
| installJournalCapabilities | `journal_version: int`, `actions: []string`: версия постоянного журнала и полный список понимаемых мутаций; локальный read-only ответ целевого бинарника. |

Manifest — UTF-8 `sha256`, два пробела и безопасный относительный путь; полное соответствие дереву выпуска. Symlink, hardlink, специальные файлы, дубликаты и неизвестные пути запрещены. `source_revision` содержит commit SHA, с возможным `-dirty` для локальной сборки.

`init` создаёт только каталоги/настройки панели и криптографический секрет, сохраняя существующий секрет и origin. `ui-access` печатает секрет только по явному root CLI-вызову. `rotate-secret` атомарно заменяет только файл секрета. Секрет никогда не передаётся через argv и не выводится обычным установщиком.

`ui-access` без параметра определяет адрес сервера и SSH-порт по `SSH_CONNECTION`, затем использует единственный публичный адрес локальных интерфейсов (предпочитая IPv4). Внешние сервисы определения IP не вызываются, поэтому выходной адрес WARP не подставляется в SSH-команду. Явный аргумент или `AWG_SSH_TARGET` переопределяет обнаружение. При неоднозначности требуется указать адрес, placeholder `YOUR_VPS` не выводится. Default SSH-пользователь — root, поскольку Web socket закрыт от обычных пользователей.

UID Web10001, Control10002, Adapter10003. Группы Web/Control10001 и Adapter/WARP10002. DockerGID читается из существующего Docker socket и сохраняется в root-only UI environment. Это разрешает Docker API исключительно адаптеру.

`journal-actions` печатает только возможности текущего бинарника. `check-control-journal <target-binary>` читает фиксированный `/var/lib/awg_vps_control/control/state.json` без блокировки writer, записи и восстановления операций; атомарная замена журнала даёт целостный снимок. Проверяются тип, владелец UID10002, права 0600, предел 8 MiB, схема и действия записей. Если журнала ещё нет, совместимость не ограничивает первую установку. При существующем журнале целевой бинарник должен быть обычным root-owned executable без symlink и прав записи группы/остальных; локальный bundle обновления распаковывают от root. Для `0.1.0-rc.1` используется известный список шести действий; для остальных выпусков обязательны корректные capabilities. Неизвестный формат, ошибка запуска или timeout означают отказ, а не согласие.

Штатные lifecycle-команды выполняют preflight до переключения выпуска. Новые rollback/install повторяют его после остановки Web и Control, чтобы между проверкой и переключением не появилась новая операция. Если первоначальная проверка уже нашла несовместимость, процессы не останавливаются. Автоматическое восстановление также сначала проверяет предыдущий выпуск; несовместимый выпуск не выбирается, текущий сохраняется для ручного восстановления. Старые установщики не содержат этой защиты: прямой ручной запуск старого `install.sh` и параллельные операции при его запуске не поддерживаются. Используйте текущий менеджер; журнал не удаляется ради отката.
