# Модели Control

Дополняет `data_model.md`. Модели созданы до Go-кода; все поля Go имеют русские inline-комментарии.

| Модель | Поля и назначение |
| --- | --- |
| Config | `SocketPath`, `HostSocket`, `StatePath`: абсолютные пути; `WebUID`: разрешённый UID Web (default 10001); `WebGID`: группа socket (10001) |
| Request | `RequestID`, `Action`, `Payload`: общий контракт Unix JSON-lines |
| Response | `RequestID`, `OK`, `Data`, `Error`: общий контракт Unix JSON-lines |
| APIError | `Code`, `Message`, `Status`: очищенный код, сообщение и HTTP-статус |
| OperationRequest | `Action`, `Payload`, `IdempotencyKey`: команда, проверенный JSON, ключ повторного запроса |
| Operation | `ID`, `Action`, `Status`, `CreatedAt`, `UpdatedAt`, `Result`, `Error`: публичное состояние операции |
| OperationRecord | `Operation`, `Payload`, `IdempotencyHash`, `Fingerprint`: операция, нормализованные параметры, SHA-256 ключа и содержимого; внутреннее хранение |
| Journal | `Version`, `Operations`: версия схемы (1) и записи операций |
| OperationLookup | `ID`: идентификатор запрашиваемой операции |
| PolicyUpdate | `WarpEnabled`, `AllowDirectWithoutWARP`: nullable bool для различения отсутствия и false; `ExpectedRevision`: обязательная SHA-256 ревизия |
| AttachRequest | `ContainerName`, `DNSContainerName`, `DockerNetwork`: валидированные имена обнаруженных ресурсов |
| LogRequest | `Source`, `Limit`: allowlist источников и количество строк 1..200 |
| Store | `mu`, `path`, `journal`, `lockFile`, `writable`: mutex, путь state-файла, журнал, flock и признак исправной записи |
| HostClient | `socketPath`: путь socket Docker adapter с UID10003 |
| Service | `config`, `store`, `host`, `wake`: настройки, журнал, интерфейс моста, уведомление последовательного worker |
| Server | `service`, `listener`, `connections`, `workers`: сервис, Unix listener, ограничитель одновременных соединений и wait group |

`IHostClient` принимает контекст и Request, возвращает Response, ошибку и признак возможной отправки запроса. Последний отличает безопасный отказ соединения от неопределённого результата после отправки мутации.

## Идентификаторы и удержание

ID операции — 32 hex-символа из crypto/rand. Request ID — 1..128 символов `[A-Za-z0-9_.:-]`. Idempotency key — 16..128 ASCII `[A-Za-z0-9_.:-]`; на диске сохраняется SHA-256. Ключ связан с SHA-256 action и канонического payload. Повтор с иным содержимым отклоняется (409).

Журнал хранит до 512 операций. Завершённые записи старше 7 суток удаляются при принятии следующей операции; для незавершённых удаление запрещено. При заполнении журнал отклоняет новые действия (429), а не теряет недавние ключи идемпотентности. Идемпотентность гарантируется в течение хранения записи; клиент генерирует новый случайный ключ для каждого нового намерения. На чтение выдаются последние 100 операций. Результат операции ограничен 8 KiB, параметры 4 KiB, журнал 8 MiB. Превышающий лимит результат заменяется безопасным указанием перечитать диагностику.

## Постоянное состояние

`AWG_CONTROL_STATE` — путь к файлу, default `/var/lib/awg_vps_control/control/state.json`. Каталог state принадлежит UID процесса, mode 0700; файл mode 0600, обычный, с одним hardlink. Родительские пути проверяются на symlink и небезопасную запись. `control.lock` предотвращает запуск двух экземпляров с одним state. Атомарная запись: temp в том же каталоге → chmod → write → fsync → rename → fsync каталога. При ошибке записи новые мутации блокируются до перезапуска/восстановления хранилища.

Незавершённые операции при старте переходят в `manual_recovery_required`; автоматического повторного исполнения нет. До фактического запроса Docker adapter сохраняется состояние `running`. Тайм-аут после отправки, неясный ответ или серверная ошибка без подтверждённого безопасного отказа дают `manual_recovery_required`. Код `operation_rolled_back` означает подтверждённый откат; в остальных случаях откат не выдумывается.

## Доступ и процесс

Контейнер запускается как `10002:10001`, с supplementary group 10002 для adapter socket. Control socket принадлежит UID процесса/GID10001, mode 0660. Все действия разрешены только Web UID10001. Локальный root и собственный UID10002 могут выполнять только `health` для проверки готовности. `AWG_HOST_SOCKET` по умолчанию `/run/awg_vps_adapter/adapter.sock`; проверяется Unix socket с владельцем UID10003 и SO_PEERCRED UID10003 после подключения. Root WARP socket напрямую в Control не монтируется.

`health` подтверждает цепочку Control → Docker adapter → Docker/WARP строгим транспортом с таймаутом 2 секунды. Успех возвращает только `{status:"ok"}`. Недоступная зависимость, некорректный ответ или его статус дают `dependency_unavailable` (503) с фиксированным сообщением, без данных о хосте. Health не выполняет сетевые пробы AWG/WARP и не подтверждает исправность VPN. Бинарный healthcheck проверяет эту готовность через Control socket.

Control не пишет в журнал сырые тела read-only снимков, пользовательские профили или ключи. Результаты мутаций ограничиваются и очищаются от полей/строк с секретами; ошибки моста не включают сырой вывод команд.

Очищенные ответы Docker adapter ограничены 512 KiB. Превышение возвращает `response_too_large` (502), без подмены формы успешного снимка. Для мутации после отправки такого запроса итог остаётся `manual_recovery_required`. Отдельный лимит 8 KiB относится только к полю результата журнала подтверждённой операции и может давать описанное выше указание перечитать диагностику.
