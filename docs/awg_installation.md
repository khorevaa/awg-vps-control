# Отдельная установка AmneziaWG

Команда `install-awg` создаёт новую установку на Ubuntu 24.04 amd64 с уже работающими rootful Docker и Compose CLI plugin версии не ниже 2. Она доступна до установки панели:

```bash
sudo bash awg_vps_control.sh install-awg --confirm
sudo bash awg_vps_control.sh install-awg --port 55424 --confirm
```

Самостоятельный helper: `sudo bash scripts/install_awg.sh --port 55424 --confirm`, порт 1024–65535. Без `--confirm` изменений нет. Установка Docker, настройка WARP, обновление ОС и обновление существующего AWG в эту команду не входят. Повторная установка намеренно отклоняется; команды `--force` нет.

## Источник и штатный формат

Используются [серверные скрипты официального AmneziaVPN 5.1.0.6](https://github.com/amnezia-vpn/amnezia-client/tree/ac175c8a8147cfe56f98c8372ec17ea2ba00bb02/client/server_scripts), commit `ac175c8a8147cfe56f98c8372ec17ea2ba00bb02`. Девять файлов скачиваются по фиксированным HTTPS URL и проверяются по `scripts/awg_upstream.sha256` до исполнения. Произвольные URL, ветки, зеркала и скрипты очистки не принимаются.

Создаются штатные контейнеры `amnezia-awg2` и `amnezia-dns`. AWG использует `awg0`, `/opt/amnezia/awg/awg0.conf`, клиентскую подсеть `10.8.1.0/24` и выбранный UDP-порт с одинаковыми внутренним и внешним номерами. Подсеть и адрес интерфейса `.0` взяты из upstream. AWG подключается к стандартному Docker bridge и `amnezia-dns-net` (`172.29.172.0/24`, bridge `amn0`); DNS получает `172.29.172.254` только во второй сети. Имена не переопределяются.

Параметры AWG 3.1 берутся из того же выпуска: Jc 4–6, Jmin 10, Jmax 50, S1–S4 12, H1–H4 1–4, случайные интервалы rekey/keepalive и включённые RandomTrailers/DisableCookies. HeaderProtectionKey и серверные ключи генерируются внутри нового контейнера. Клиентские профили и peers не создаются. Отсутствие `clientsTable` после чистой установки штатно и поддерживается панелью. Шаблон AWG 3.1 в AmneziaVPN 5.0.3.0 совпадает с 5.1.0.6; фактическое подключение клиента проверяется отдельно.

Официальные Dockerfile используют `amneziavpn/amneziawg-go:latest` и `mvance/unbound:latest`. Перед сборкой helper загружает эти конкретные образы, сохраняет фактические ID и RepoDigest и подставляет выбранный digest в `FROM`. Это закрепляет базу данной установки; сетевые пакеты `apk` внутри официального Dockerfile остаются зависимостью upstream. Полностью воспроизводимая сборка не заявляется. Штатный AWG запускается privileged с `/lib/modules`; доступ этого доверенного контейнера соответствует официальному установщику Amnezia.

## Проверки до изменения сервера

- Нужны root, Ubuntu 24.04 amd64, работающий локальный Docker Unix socket, Compose CLI plugin >= 2, `/dev/net/tun`, `/lib/modules` и уже включённый `net.ipv4.ip_forward=1`.
- Проверяются остановленные и работающие контейнеры по штатным именам/образам AWG/DNS, native build paths и host-каталоги AWG (включая `/etc/amnezia/amneziawg`), существующая привязка панели, журнал установки, занятые UDP-порты и адресные пересечения с host routes и Docker networks. Произвольно переименованные сторонние образы не распознаются универсально; профиль установки предназначен для проверенного пустого VPS.
- Default Docker bridge должен быть пустым. Существующая сеть `amnezia-dns-net` либо bridge `amn0` не присваиваются проекту. Установленные контейнеры панели с `network_mode: none` не мешают.
- Операции сериализуются общей блокировкой `/run/awg_vps_install.lock`. Она координирует команды проекта; параллельно запускать установку Amnezia или другие изменения Docker нельзя.

`prepare_host.sh` выполняется один раз для AWG после проверок и создаёт общую DNS-сеть. Каталог сборки DNS создаётся отдельно с правами `0700` после повторной проверки отсутствия и безопасности пути; закреплённая сеть проверяется до и после этого шага. Повторный upstream prepare не вызывается: его проверка сети через `grep -q` ненадёжна при включённом `pipefail`. Вызовы `sudo` разрешают точные операции `mkdir`, `chown` и Docker из закреплённых скриптов; Docker принудительно использует локальный сокет и отдельный пустой config. Значения шаблонов заменяются по явному перечню. Внутренние переменные генерации ключей не раскрываются на хосте.

`configure_container.sh` выполняется один раз внутри проверенного нового container ID с `umask 077` и остановкой при ошибке. `start.sh` копируется в штатный путь и запускается отдельно: его ожидаемый первый `awg-quick down` не прерывает дальнейший запуск. Готовность определяется по интерфейсу, listen-port, native файлам, DNS и всем восьми штатным правилам firewall/NAT из upstream `start.sh`. Helper повторяет проверки интерфейса/порта/правил в течение 90 секунд: `iptables -C` подтверждает INPUT/FORWARD/OUTPUT для `awg0`, два forwarding rules в `eth0`/`eth1`, ESTABLISHED/RELATED и оба POSTROUTING MASQUERADE. Каждая группа проверок правил ограничена 10 секундами внутри закреплённого контейнера, ожидание xtables lock — одной секундой на правило; Docker-вызовы также имеют конечный deadline. Отсутствие правила не исправляется скрыто и не допускает `succeeded`: результат требует ручного восстановления. Успешный запуск фоновой команды сам по себе готовность не подтверждает.

`setup_host_firewall.sh`, `install_docker.sh`, удаление контейнеров, WARP и изменение маршрутов/политик панели не запускаются. Проверяются сохранность default routes, policy rules, правил INPUT и маршрута до текущего SSH-клиента, если `SSH_CONNECTION` доступен. Установка добавляет штатные Docker сети, NAT и правила публикации UDP; это ожидаемые изменения. Независимая проверка нового SSH-подключения и VPN handshake остаётся частью приёмки.

## Приватное состояние установки

Каталог `/var/lib/awg_vps_control/awg_install` принадлежит root, имеет права `0700`; файлы — `0600`. Символические ссылки и небезопасные владельцы/права в управляемых путях отклоняются. Перед первой Docker-операцией сохраняется `state.json`. Журнал обновляется атомарно через временный файл, `sync` и rename.

| Поле | Содержание |
| --- | --- |
| `schema_version`, `operation_id` | Версия формата и ID попытки |
| `status`, `step`, `exit_code` | `installing`, `succeeded` либо `manual_recovery_required`; текущий шаг и код завершения |
| `started_at`, `updated_at`, `manager_version` | Время UTC и версия менеджера |
| `upstream_repository`, `upstream_release`, `upstream_commit` | Официальный источник |
| `sources` | Путь и SHA-256 каждого скачанного файла |
| `rendered_manifest_sha256` | Хеш перечня подготовленных файлов; сам перечень хранится рядом |
| `container_name`, `dns_container_name`, `interface`, `listen_port`, `client_subnet`, `docker_network`, `docker_subnet` | Запрошенная фиксированная топология |
| `container_id`, `dns_container_id`, `network_id` | Подтверждённые созданные ресурсы; до соответствующего шага пустые строки |
| `awg_base_image_id`, `awg_base_digest`, `dns_base_image_id`, `dns_base_digest` | Выбранные официальные базовые образы |
| `awg_image_id`, `dns_image_id`, `config_revision` | Собранные образы и SHA-256 native конфига |

Скачанные исходники, подготовленные скрипты, контрольные суммы и ограниченные build logs хранятся в этом приватном каталоге. Ключи, HeaderProtectionKey, полный server config, client profiles и SSH credentials в журнал не записываются. Вывод генерации конфигурации подавляется. Журнал не заменяет `/var/lib/awg_vps_control/host/installation.json` и не предоставляет разрешение изменять существующую установку.

После ошибки или прерывания ресурсы автоматически не удаляются и конфигурация повторно не генерируется. Состояние требует ручной проверки по сохранённому шагу и ID. При `SIGKILL`/отключении питания может остаться `installing`; следующая попытка также отклоняется. Удалять этот каталог и повторять установку без проверки созданных контейнеров нельзя.

## Подключение панели

После успешной установки установите панель обычной командой `install-ui`, затем выполните:

```bash
sudo awg-vps-control attach amnezia-awg2 amnezia-dns-net amnezia-dns
sudo awg-vps-control doctor
```

Attach перечитывает native конфиг и закрепляет container ID. Он не создаёт WARP-маршруты. WARP настраивается отдельным действием под независимым safety-таймером с подтверждением нового SSH; установка AWG сама его не включает. Успешная установка сервера ещё не означает проверенного VPN-подключения: профиль клиента выдаётся штатной Amnezia, затем отдельно проверяются handshake, DNS и HTTPS.
