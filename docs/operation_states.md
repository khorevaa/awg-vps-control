# Состояния операций

`queued → running → verifying → succeeded` — нормальное выполнение. Host bridge проверяет результат до успешного ответа; Control отмечает verifying перед сохранением итогового результата. При подтверждённом откате: `rolling_back → rolled_back`. При безопасном отказе до изменения: `failed`. При неопределённом результате/ошибке восстановления: `manual_recovery_required`.

При перезапуске Control прежние незавершённые операции не воспроизводятся автоматически. Их итог неизвестен до повторной диагностики, особенно для ручного AWG restart. Они переходят в `manual_recovery_required`. Идемпотентный повтор возвращает ту же операцию; тот же ключ с другим содержимым даёт 409.

Намерение сохраняется до вызова host bridge. Host проверяет policy revision и использует общий lock с supervisor. Неудача сохранения intent блокирует действие. Тайм-аут после отправки мутации не считается доказательством отсутствия изменения.

Состояние службы WARP, health Web и готовность supervisor не заменяют проверку передачи данных. Прямой выход допускается только по таблице политики из плана. Ручное отключение использования WARP отличается от аварии ранее включённого WARP.
