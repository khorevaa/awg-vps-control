# Готовность первого выпуска

## Управление клиентами в develop

12 ноября 2026 года `0.2.0-dev.1` установлена на тестовую установку поверх первого
RC. Обновление сохранило AWG/DNS ID/PID, native конфигурацию, сеть и доступ.
Это продолжение разработки, а не новый опубликованный стабильный релиз.

- Linux build/vet, существующий `go test` (оба модуля без Go test-файлов), gofmt,
  JavaScript/Bash syntax и actionlint прошли.
- 35 проверок через настоящий Web/Control/Adapter: создание, идемпотентность,
  разовая выдача `.conf`, соответствие private/public key, PSK, адреса и параметров
  AWG, переименование, отзыв и сохранность прежних peers. Внешнее последовательное
  изменение `clientsTable` обнаружено; неизвестные поля и дата сохранены.
  Повторное скачивание даёт 410; перезапуск Adapter теряет невыданный профиль,
  после чего клиент отзывается штатно. Ключей в журнале нет.
- 19 проверок Chromium через настоящую панель: создание, скачивание, переименование,
  отзыв, сохранность исходного списка и отсутствие frontend/transport ошибок.
  Дополнительно 10 сценариев интерфейса проверены на синтетических данных.
- Официальный JetBrains HTTP Client CLI выполнил все три `.http` файла: 26 запросов
  и статусных проверок, без ошибок. HTTP-тесты не изменяют VPN.
- AWG не перезапускался при CRUD и перезапуске Adapter. Политика WARP не менялась,
  серверные HTTPS/DNS пробы прошли после удаления всех временных клиентов.
- Откат к RC с новым журналом отклонён до смены current и до остановки служб;
  PIDs панели и AWG сохранились. Строгая проверка прав также отклонила первый
  локальный архив с правами Windows; корректная распаковка решила проблему,
  требования к правам не ослаблялись.

Пользователь подтвердил успешное подключение настоящим внешним VPN-клиентом
с новым профилем, созданным панелью. Сценарий «создать клиента → скачать `.conf`
→ подключиться» проверен на установленной `0.2.0-dev.1`; источник подтверждения —
сообщение пользователя, отдельный серверный замер этой сессии не выполнялся.

Остаются отображение изменений в приложении Amnezia и проверка отзыва после
отдельного ручного перезапуска AWG. Пробы DNS/IPv6/административных исключений
внешнего клиента, открытые для первого RC, также остаются отдельными проверками.

## Опубликованный предварительный выпуск

Состояние на 12 ноября 2026 года: [предварительный выпуск `0.1.0-rc.1` опубликован](https://github.com/khorevaa/awg-vps-control/releases/tag/v0.1.0-rc.1); стабильный `0.1.0` **не готов**. Кандидат сохраняет проверенную реализацию `0.1.0-dev.2` и явно открытые DNS/IPv6/административные сценарии настоящего клиента. Этот документ описывает фактически выполненные проверки, а не только наличие кода.

Для опубликованного кандидата отдельно проверены анонимное скачивание архива и всех слоёв обоих GHCR-образов, SHA-256, версия и source revision. Штатная команда `update-ui v0.1.0-rc.1` обновила панель из GitHub Release: три контейнера здоровы, native AWG/DNS ID/PID и файлы, политика, маршруты, firewall и доступ сохранены. Серверные HTTPS/DNS и повторные 45 браузерных проверок прошли на установленном release bundle. Проверка установленного каталога учитывает штатный генерируемый `runtime.env`; полный manifest исходного bundle проверяется установщиком до его добавления.

После прежней потери SSH независимое аварийное отключение проверено, новое подключение WARP сохраняет SSH. Полная клиентская и сетевая приёмка ещё не завершена. Пока сетевые сценарии не приняты, использовать сборку как стабильный WARP-менеджер нельзя.

Проверка HTTPS/DNS из сетевого namespace не заменяет внешнего AWG-клиента. Проверки первой архитектуры UI не засчитываются повторно для текущей сборки. Новые Go-тесты не создавались; `go test` в текущих модулях сообщает об отсутствии тестовых файлов. HTTP-прогон использовал исходные Host/Origin/Cookie и реальные ответы через Unix socket; VPN-операции не выполнялись. JUnit содержит 54 служебных и пользовательских testcase без ошибок; это 18 запросов и 18 статусных assertions, а не 54 разных сценария.

Подробные результаты, реквизиты стенда и исходные снимки хранятся только локально. В публичный документ не включаются адреса, имена серверов, ключи, токены, клиентские профили или сырые журналы.
